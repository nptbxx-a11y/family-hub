# Mahjong Solitaire + Games Page — Design

**Date:** 2026-11-01
**App:** family-hub (Ozzy & Tommy)
**Status:** Approved design

## Summary

Add a single-player **Mahjong Solitaire** game (the tile-matching puzzle) and a
**🎮 Games** page that collects the app's games. The sidebar's "⚔️ All Aboard"
link is replaced by one "🎮 Games" link; the Games page shows a card per game.

"Just for fun": no scores, no database, no Supabase changes.

## Games page

- New route `/games` (`GamesHub.jsx`), one card per game:
  - ⚔️ **All Aboard** — Battleships for two · *2 players* → `/battleships`
  - 🀄 **Mahjong** — Match the tiles, clear the board · *Solo* → `/mahjong`
- Sidebar: "⚔️ All Aboard" link replaced by "🎮 Games" (`/games`). It shows as
  active on `/games`, `/battleships` and `/mahjong`.
- Each game page gets a small "← Games" link at the top.
- `/battleships` keeps its URL. The archived World Cup is not listed.

## Mahjong — gameplay

- **Modes:** Quick (72 tiles, phone-sized pyramid, max 8 tiles wide) and
  Classic (144 tiles, traditional "Turtle"). Chosen when starting a game.
- **Free tile:** nothing on top of it AND its left or right side is open.
- **Play:** tap a free tile → it is selected (gold glow); tap a matching free
  tile → both are removed. Tapping the selected tile deselects; tapping a
  non-matching free tile selects that one instead; tapping a blocked tile does
  nothing.
- **Matching:** identical tiles match; any flower matches any flower; any
  season matches any season.
- **Blocked tiles are shaded** darker so free tiles are easy to spot.
- **Win:** board cleared → celebration overlay with the time and "New game".
- **No moves left:** banner offering Shuffle.
- **Timer + tiles-left** shown for fun; nothing is recorded.

## Helpers

- 💡 **Hint** — highlights one valid free pair (or says to shuffle if none).
- 🔀 **Shuffle** — re-deals the remaining tiles' faces among the remaining
  positions, guaranteed solvable from the current state. Clears undo history.
- ↩️ **Undo** — restores the last removed pair.
- ✨ **New** — back to the mode picker.

## Guaranteed-solvable deals

Deals are generated by simulating play: from the full layout, repeatedly pick
two random currently-free positions and remove them, recording the order. Each
recorded position-pair is then assigned a matching tile pair. The recorded
order is a valid solution, so every deal is solvable. If the simulation gets
stuck (fewer than 2 free positions while tiles remain), it retries.

## Tiles

- Standard 144-tile set: dots 1–9, bamboo 1–9, characters 1–9 (×4 each),
  winds 東南西北 (×4), dragons 中 發 白 (×4), flowers 🌸🌺🌼🌻 and seasons
  🌱☀️🍂❄️ (×1 each).
- Grouped into 72 matchable pairs. Classic uses all 72 pairs; Quick uses 36
  pairs chosen at random.
- Faces drawn by the app (no images/fonts to load): dots and bamboo as SVG;
  characters, winds and dragons as Chinese characters; flowers and seasons as
  emoji. Ivory tiles with a 3D edge on the dark aurora theme.

## Board geometry

Positions use half-tile units `(x, y, z)`; a tile occupies `[x, x+2) × [y, y+2)`
on layer `z`.

- **Covered:** some tile at `z+1` with `|dx| < 2` and `|dy| < 2`.
- **Left/right neighbour:** same `z`, `dx = ∓2`, `|dy| < 2`.

The board scales to fit the available width (and height, for landscape);
higher layers are offset slightly up-left for depth.

## Persistence

The game in progress is saved to `localStorage` (key `mahjong:v1`) on every
change and restored on load, so leaving the page doesn't lose it. Each phone
has its own game. All storage access is wrapped in try/catch; the game works
without it.

## Structure

**Pure logic (unit-tested with Vitest), `src/mahjong/`:**
- `layouts.js` — Quick (72) and Classic (144) position lists.
- `tiles.js` — tile set, pair grouping, match keys.
- `engine.js` — free/cover checks, matching, hint, solvable deal, shuffle.

**UI, `src/components/`:**
- `Mahjong.jsx` — page: mode picker, top bar, toolbar, banners, win overlay,
  persistence, timer.
- `MahjongBoard.jsx` — scaling and positioning.
- `MahjongTile.jsx` — tile faces.
- `Mahjong.css`, `GamesHub.jsx`, `GamesHub.css`.

**Modified:** `App.jsx` (routes), `NavBar.jsx` (Games link), `Battleships.jsx`
(← Games link), `CLAUDE.md` (routes/features).

## Out of scope

Scores, leaderboards, daily challenges, database storage, multiplayer,
traditional 4-player mahjong, extra layouts beyond Quick and Classic.

## Addendum (2026-11-04): no shading, deeper tiles, players + leaderboard

**Approved changes:**

- **No shading.** All tiles render the same; blocked tiles are no longer
  darkened. Tapping a blocked tile does nothing except a short wiggle
  (reduced-motion: no wiggle).
- **15% more 3D.** Tile edge and drop-shadow offsets ×1.15; per-layer offset
  `DEPTH` 0.1 → 0.115.
- **Who's playing.** The board picker has an Ozzy / Tommy toggle, defaulting to
  the device's existing `battleships_player` localStorage value (shared with
  All Aboard). A game can't start until a player is chosen. The player shows in
  the top bar.
- **Scores (database).** On clearing a board, one row is written to
  `mahjong_scores` (`player`, `mode`, `seconds`, `assisted`, `created_at`).
  Family-only RLS policy (same as every table); realtime enabled. A game is
  `assisted` if Hint or Shuffle was used (Undo does not count).
- **Leaderboard.** On the picker, with Quick / Classic tabs (separately — times
  aren't comparable). For each player: best time from **clean games only**, and
  total wins (all cleared boards). Leader (fastest best) highlighted in gold; a
  tie has no leader.
- **Win screen** says one of: "New personal best!", "Time saved", "Hint/Shuffle
  used — not on the leaderboard", or "Couldn't save your time" (save errors are
  shown, never swallowed).

**Pure logic** (`src/mahjong/leaderboard.js`, unit-tested): `summarize`,
`leaderOf`, `isPersonalBest`, `formatTime`.
